# DoAide Khata — डिजिटल उधार खाता

A WhatsApp-style digital ledger (khata) for Indian shopkeepers. Track udhar, collect payments with WhatsApp reminders and UPI links, make GST bills, and export PDF statements. Hindi + English, mobile-first, and no login needed.

**A DoAide Product** · https://khata.doaide.com

## Features

- **Customers**: name and mobile number, with live balances (lena hai / dena hai)
- **Entries**: "Gave" (udhar) or "Got" (payment) with amount, note and date. Tap any entry to edit or delete it.
- **Customer ledger**: chat-style bubbles with a running balance after every entry
- **Dashboard**: total outstanding, advance held, today's collection, udhar given today, top dues, and dues unpaid for 30+ days
- **WhatsApp reminders**: a bilingual message with the amount due and a `upi://pay` link built from the shop's UPI ID
- **GST bills and receipts**: CGST+SGST or IGST, PDF download/share, numbering per year, optional "add to khata as udhar"
- **PDF ledger statement**: generated by the backend (reportlab) and shared through the phone's share sheet where supported
- **Quick entry**: type or speak (Web Speech API) e.g. "Ramesh ko 500 udhar diya". Gemini on the backend parses the sentence; a keyword parser takes over if Gemini is unavailable.
- **No-login mode**: everything lives in `localStorage`. Optional Google sign-in syncs across devices (last-write-wins per record, tombstones for deletes). JSON backup and restore are also available.

## API

| Method | Path | Notes |
|---|---|---|
| GET | `/api/health` | `{"status":"ok"}` |
| GET | `/api/config` | public: Google client ID, whether AI is enabled |
| POST | `/api/auth/google` | Google ID token → 30-day HMAC session token |
| POST | `/api/sync` | Bearer session; merges and returns the ledger |
| POST | `/api/ai/parse` | sentence → `{customer_name, type, amount, note}` (60/hour per IP) |
| POST | `/api/bill/calculate` | GST totals |
| POST | `/api/pdf/bill`, `/api/pdf/ledger` | PDF downloads |
| GET | `/sitemap.xml`, `/robots.txt` | served by the backend, not the SPA |

## Local setup

```bash
# backend
cd backend
python3.13 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
cp .env.example .env   # set GEMINI_API_KEY, GOOGLE_CLIENT_ID, SESSION_SECRET
.venv/bin/pytest
.venv/bin/uvicorn app.main:app --port 3101

# frontend
cd frontend
npm install
npm test
npm run build          # static files in dist/, served on 3102
```

The Gemini key is a **backend-only** env var. The frontend never sees it.

## Deploy (Hetzner 89.167.8.178)

1. rsync the repo to `/opt/DoAide-Khata`, then create `backend/.venv` and `backend/.env`
2. `cd frontend && npm ci && npm run build`
3. Install `deploy/*.service` into `/etc/systemd/system/` and run `systemctl enable --now doaide-khata-api doaide-khata-web`
4. Add `deploy/Caddyfile.snippet` to the Caddyfile, add the DNS record `khata.doaide.com`, and add the domain to the Google OAuth client's authorized JavaScript origins
5. Optional: set `KHATA_PDF_FONT` to a Noto Sans TTF so PDFs render `₹` and Hindi names (the default Helvetica shows `Rs.`)
